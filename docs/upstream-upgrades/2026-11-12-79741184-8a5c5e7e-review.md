# 2026-11-12 — nxnative 79741184 → 8a5c5e7e review

**Status: adopted and published in 0.1.4.3 at the maintainer's explicit direction on 2026-11-12.** Previous pin: `79741184af1558fa1ada0f61741eeecbd615b3f6`. New pin: `8a5c5e7e1ee606c650fe1aef6959a83009b6a2fc` (upstream `main` fetched again just before adoption), **152 commits, 572 files**, all from 9–12 November. The maintainer asked to publish 0.1.4.3 with the latest upstream engine rather than keep the 0.1.4.2 pin. That overrides the 0.1.4.3 readiness note's "defer speculative engine upgrades" for this release only. **This review does not claim a real build or a visible launch on the exact new commit.** Upstream commits after 8a5c5e7e are outside it.

Upstream changed quickly in this range. Several commits repair regressions that other commits in the same range introduced: the iOS link, the gfx tests, lint baselines, `BrokenProcessPool` in the new shader workers (bcc4483d after 8b55ebb3), and the native translator on macOS 26 (380ff71a after 641636e2). That is a reason to validate on this Mac before reporting the engine as working, not a reason to skip the release.

## Integration decisions

| Capability / change | Decision | Reason / practical effect |
|---|---|---|
| **No .NET** (641636e2, 380ff71a) | **Backend + Setup/UI change** | `EnginePackageReader`'s probe called `engine.configure_dotnet`, which the engine removed. With a Newest-engine checkout at or after 641636e2 (the maintainer's released app was at a77c0ee8), **every NSP/XCI/NSZ/XCZ add failed** with `module 'nxlibrary_probe' has no attribute 'configure_dotnet'`, reproduced with the exact probe. It is now called only when it exists, and a regression test covers an engine without it. The .NET 10 SDK card, its Microsoft downloader (`DotnetRelease`), the .NET row in Settings → Engine, the build gate's ".NET 10 SDK is missing" issue and the diagnostics line are removed: they would block or prompt for a tool the engine no longer uses. Setup always moves the checkout to at least this pin, and Newest only moves forward, so no supported engine needs .NET. Get ready now shows five cards (3 + 2). The `translator` failure now says the engine's translator is missing or damaged and points at the nxnative engine card, matching the new engine message; it no longer suggests installing .NET. |
| **Tools in sessions of their own** (0b124486, 84d36c63) | **Backend** | NX Library stopped a build with `killpg(SIGTERM)` and `SIGKILL` 5 s later, both on the script's group. Each tool now leads its own session, which neither signal reaches; the engine's own SIGTERM handler stops it within 5 s. So a SIGKILL at 5 s could race the engine, and **quitting NX Library mid-build (immediate SIGKILL) left the shader build or xcodebuild running with no parent**. Now a cancel waits 8 s before killing, a quit sends the same SIGTERM and waits up to 8 s, and the fallback kills the build's group and every descendant listed before any is killed. Three tests use real process trees with a tool in its own session. |
| **Cloud-save pull journal** (e6048dea, 06c2ea4c) | **Backend** | While `<save>.pull` exists, the game's next start puts this device's save back. NX Library already leaves the file alone (it reads only `save/` and `save_device/`), and refuses writes while cloud saves are on. It now also refuses an import or restore while a journal is pending (cloud turned off after a cut-short pull) and says to play once first. Tested; the message is translated into six languages. |
| **Cloud-save conflict question** (07d6ea46, 0a764c09) | **Not adopted in this release (follow-up)** | The engine asks only in its launcher (window shown, or `window.show` off without `DM_LAUNCHER=0`). NX Library starts every game with `DM_LAUNCHER=0` so its Game options replace the window. Its players therefore keep the host's previous rule (the newer file wins, the other kept in `-backups`), the same as 0.1.4.2. Upstream documents why that rule can lose progress. Fixing it needs a product decision: NX Library's own Play-time comparison through the documented formats, or letting the engine's alerts run. Neither is built or claimed here. |
| Render scale above 100 % (b84ee29a) | **Not adopted (follow-up)** | Only Hades II offers it. NX Library's fixed 50–100 % row keeps working; the engine's own range is not exposed above 100 %. |
| `--fallback-icon` (5714e328) | **Not adopted** | Same reasoning as `--icon` in the 0.1.4.2 review: NX Library's reversible icon writer keeps true original provenance; a packed stand-in would look like the game's own icon. |
| Shader/pipeline, GPU memory, textures, movies, input, ProMotion 60 fps, Switch 2 full docked picture, -O2 host | **Backend** | Takes effect in rebuilt game apps; installed apps keep their engine until rebuilt. |
| New or newly playable games (Red Dead Redemption, TUNIC, both Ori games, Metroid Prime 4: Beyond, The Binding of Isaac: Rebirth, PRAGMATA, Diablo III, Diablo II: Resurrected, Nintendo Switch Sports Resort, Hades II 1.0.141667, Mario Kart World 1.8.0 frame step, Smash language restart, Drag x Drive) | **Backend** | Profiles come from the engine. None of these titles was tested by the maintainer in this review. |
| Diagnostics (`DM_IMU_*`, `DM_NVN_*` measurement switches, `DM_CRASH_PEEK`, `DM_GFX_SCALE`…) | **No UI** | Guardrail: diagnostic switches stay out of the main UI. |

## Verification and adoption record

- The engine's message table (`PortingFailureReasonTests`, with `NX_TEST_ENGINE_COMMIT` set) and `EngineRuntimeRequirementsTests` passed against upstream `main` before the change, on the 0.1.4.3 candidate 6ab6ba1 in a temporary worktree.
- The new and changed suites pass: package probe without `configure_dotnet`, Setup without .NET, build stop with tools in their own session (quit with a graceful engine, quit and cancel with a script that ignores SIGTERM), refusal while a pull journal is pending. The localization check passes for six languages. The full suite and the Dev build are recorded in the release notes for this candidate.
- Real build on exactly 8a5c5e7e, in NX Library Dev after Setup moved the checkout: The Legend of Zelda: Ocarina of Time (0400486024DEC000, v131072) built with every stage ok. Shader split 42,848 shaders; Mac shaders 42,848 of 42,848 ready, 0 from the cache (the chain change), in 1,179 s; Mac host 15 s; pipeline archive `applegpu_g17s`, 4.3 GB, in 802 s; Mac app 34.5 GB in 121 s; the icon was applied. The installed app's `DMCommit` is `8a5c5e7e1ee6`, and the game was running when the maintainer asked to publish.
- Not performed before publication: the cancel and quit-mid-build checks on a real build (covered only by the automated process-tree tests), an NSP/XCI Add Game on the new engine, and other games. These remain open manual checks.

## Focused maintainer check

1. **Setup / Settings → Engine.** Update to 8a5c5e7e: the released app's Newest choice at a77c0ee8 is included in the pin, so it is retired and the engine card offers **Update**. Get ready shows five cards (Xcode, Metal compiler, nxnative engine, Python and tools, Keys) in a 3 + 2 grid, with no .NET card. The compatibility gate is green, Metal 32023.922.
2. **Add Game with an NSP/XCI** (the reproduced failure). Title and version are read; no `configure_dotnet` error.
3. **Build one real game** with its existing cache. The shader step reports re-translation for the new chain. Check that the build finishes and the app launches to a visible screen.
4. **Cancel a build** during the shader step: it stops within about 8 s as **Cancelled**. Then run `pgrep -fl "dmsh|metal|xcodebuild"`: it should list nothing left from the build.
5. **Quit NX Library during a build**: it closes within about 8 s. Run the same `pgrep`: nothing left running.
6. Saves panel with cloud saves off: import/restore still work normally (there is no journal in normal use).
