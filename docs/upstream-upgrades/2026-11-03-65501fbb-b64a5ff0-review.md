## Product decision

The upgrade addresses concrete runtime and build issues: stalled audio startup, alignment-related boot crashes, texture and render-target correctness, shader-build memory use and obsolete shader caches. Upstream measurements are specific to their games and routes; they are not performance results for games tested here. The last runtime change affects constant-buffer allocation across NVN games, so the certified game check remains necessary even though the Metal compiler is unchanged.

## Toolchain and frontend contract

- Metal remains `32023.922`, Apple asset `27B47`; minimum Xcode remains `27.2` and .NET SDK major remains 10. No asset-table or runtime-lock change is needed.
- CLI help, `docs/env_switches.tsv`, the shader-chain lock and changed profile/documentation files were reviewed. The existing mac-app builder flags remain present.
- Old-key errors retain the required firmware version when known, using the final preflight error rather than an earlier package probe. An unknown future firmware uses the existing up-to-date-console guidance. Key names/values are not inserted into the player-facing explanation.
- A missing common ticket is a package issue: its explanation asks for a complete export, rather than replacement keys or a bypass.
- Cache cleanup can be slow, particularly for a large existing cache on an external drive. `Cleaning shader cache` replaces the ETA while this work is reported. Stage, step, cleanup completion and build termination clear the activity. Progress is not advanced by the cleanup message.
- Settings → Library uses one **Scan game apps** action for discovery and refresh, with the existing folder bounds and preservation rules. Broader non-nxnative app import and the always-accessible guide are deferred.
- No change to source linking, key storage, saves, library schema or normal launch settings. No engine patch or automatic tracking of main.

## Adoption and rollback

The application pin changed after the real-game validation. The ordinary pin-dependent suite passed after adoption, with README and architecture updated together. The upstream-status cache already rejects entries whose base commit differs from the pin.

The upgrade does not rebuild installed games automatically. Existing game apps remain playable while Setup prepares a new engine. Rollback uses the previous launcher/pin and engine checkout; older shader-chain cache entries may have been pruned, so a later rebuild can need to regenerate them. Source files, installed app and save data are independent of that cache cleanup.
