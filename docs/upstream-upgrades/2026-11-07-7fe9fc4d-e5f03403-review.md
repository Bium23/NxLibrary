## NX Library changes

- **Reading packages (5c4dc18f).** NX Library's metadata bridge called the engine's `is_merged` and `package_title_reader`, which are gone. It now reads every package in one `package_reader` run, as the engine does for the build, and takes each package's title ID and version from its content metas, never from its file name. A package the engine cannot read is skipped and named, as before. Keys that cannot open the packages stop the scan with the engine's own line, which names the missing key (never a value). Engines before 5c4dc18f still go through the older reader.
- **Version to pack (`-p`).** NX Library passes the selected version to the engine, which now refuses one its content metas do not show. Versions come from the content metas (above), and a base game built alone is packed at its own version: `v0` for most, `v65536` for a base game the eShop serves at 1.1.0 (Castlevania: Belmont's Curse).
- **Failure table.** "no NSP with a readable title ID in" became "no game package with a readable content meta in": **No game found in the files** reads both.
- **`game` event (d70e6a3a).** Read and kept out of the build log, like `shaders_stale`: a `say` with the same news follows each. Its name, version and icon are not used: NX Library already has the game's name, its version from the content metas, and its artwork.

## Toolchain and frontend contract

- Capability markers (`--title-id`, `import pack_dump`, `import pack_nup`, `survey_nup`, `survey_dump`), the other progress events, the `Mac shaders` stage and its steps are unchanged.
- Every engine message the failure table reads is still printed (`PortingFailureEngineTests` against `e5f03403`).
- No change to source linking, key storage, library schema or launch settings. No engine patch; main is not followed automatically.
- A library entry scanned before this change keeps the version it was given then. An NSZ update whose file name carried a wrong `[v<N>]` tag would now stop its rebuild with the engine's "the version to pack (-p / PACKAGE) is not in the folder"; adding its files again reads the right version.
