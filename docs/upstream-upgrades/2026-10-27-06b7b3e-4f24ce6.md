```text
metal-tt failed for applegpu_g17s (exit 1)
Fragment input(s) `user(locn0)` mismatching vertex shader output type(s)
or not written by vertex shader
```

The upstream shader fix is in this range. The new pin also contains the `-O1` shader front end, which removes the pathological 25-minute pipeline compile that made the old build appear frozen.

## Integration found and fixed

The old pin did not enforce the Metal compiler inside the engine. The new pin does:

- `scripts/build_ipa_from_nsp.py` stops on an untested Metal compiler unless `--allow-other-metal` (or `DM_ALLOW_OTHER_METAL=1`);
- NX Library already has the explicit, persisted **“Build anyway with an untested toolchain”** override;
- the app was not passing the new flag, so the override UI would have been ignored at the engine gate.

Fixed in:

- `Sources/NXLibraryCore/Services/BuildCommandBuilder.swift` — `allowUntestedToolchain` appends `--allow-other-metal`;
- `Sources/NXLibrary/ViewModels/AppViewModel.swift` — passes the persisted override;
- `Tests/NXLibraryCoreTests/BuildCommandBuilderTests.swift` — regression test.

## UI decision

No new UI element is justified by this upgrade. The existing screens already expose:

- FPS target, docked/handheld, render scale, MetalFX, Metal HUD, language, rumble and fullscreen;
- build stage, progress, ETA, log and cancellation;
- the certified/blocked/override toolchain state;
- the read-only upstream changelog with commit list and GitHub compare link.

The new engine features are automatic behavior or diagnostics. A future **“upgrade review” summary** in the Engine card (categorized notes and a reviewed badge) is a reasonable option if upgrades become frequent, but it is not needed now.

## Not adopted

- `DM_RUMBLE_MIN`: game-specific tuning; the existing rumble gain is enough.
- `DM_MEASURE_LOCK`, `DM_NVN_PROGTRACE`, `DM_NVN_VSDUMP*`, `DM_PROBE_*`: diagnostic tooling, not user settings.
- `e09ff95` (**RomFS streaming**): one commit newer than the pin, large host/filesystem change, no SMO validation yet. Deliberately left out.

## Out of scope

MacNativeGames is a separate project. Its Odyssey port supports **1.3.0 only** and rejects the user's **1.4.1** by hash; it is not a second backend for this game. TotK/BotW are its supported titles. A static catalog or external-app import remains a separate decision.
